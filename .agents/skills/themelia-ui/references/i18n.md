# Localization

The kit ships English defaults and no translation machinery. Every string it owns is
overridable, and nothing in it inspects `navigator.language` or imports a translator.

## Strings

Each family exports a `*Strings` interface and a `default*Strings` object, and takes a
`strings` prop:

```tsx fragment — shape only, not a program
<Copyable strings={{ copy: "Kopieren", copied: "Kopiert" }} value={apiKey} />
```

Overrides are **deep-merged**, one key at a time. A nested group can be overridden
partially, and every sibling key keeps its default:

```tsx fragment — a template with a hole in it
<DataTable strings={{ pagination: { previous: "Zurück", next: "Weiter" } }} />
```

Where a family types its prop as `Partial<…Strings>`, TypeScript still asks for each nested
group whole; spread the group's default, for example
`kind: { ...defaultTransactionStrings.kind, refund: "Rückerstattung" }`.

### A sentence is one key, not several

Copy with a value in it is a **function**, not a template assembled at the call site:

```ts fragment — shape only, not a program
remove: (name: string) => `Remove ${name}`
position: (name: string, index: number, total: number) =>
  `${name}, position ${index} of ${total}. Use the arrow keys to reorder.`
```

Word order, the words between the parts, and the plural form belong to the sentence.
`${strings.remove} ${file.name}` still hardcodes the space and the order, and
`count === 1 ? "person" : "people"` is an English plural rule; most languages have more than
two forms. Replace the whole function, not the words inside it.

### What consumers can rely on

- Component-owned visible and accessible copy belongs to the family's typed `strings`
  contract, including placeholders, titles, alternative text, and announcements.
- Product/domain copy still arrives through application data, children, or documented props;
  the package does not translate it or decide which message catalogue to use.
- Exported `default*Strings` objects provide the complete shape for a locale adapter.
- Decorative `alt=""` remains valid and should not be replaced with spoken copy.
- Sentence functions own word order and plural decisions. Consumers should replace the
  function rather than concatenate translated fragments around a runtime value.

## Formatting

Locale and formatting policy live in the provider, not in each component:

```tsx fragment — shape only, not a program
<UIRoot config={{ formatting: { locale: "de-DE" }, money: { defaultCurrency: "EUR" } }}>
```

The display primitives — `Money`, `Date`, `DateTime`, `FileSize`, `Number` — read it. A
component takes a prop first, then the provider, then its own fallback, so a one-off stays a
one-off.

### Dates need two things, and they are separate

```tsx fragment — shape only, not a program
import { de } from "date-fns/locale"

<UIRoot config={{
  formatting: { locale: "de-DE" },        // Intl: numbers, money, relative time
  dates: {
    locale: de,                            // date-fns: month and weekday NAMES
    weekStartsOn: 1,                       // which column a calendar begins in
    format: "dd.MM.yyyy",
    timeFormat: "HH:mm",                   // "p" follows the locale's own convention
  },
}}>
```

`dates.locale` cannot be derived from `formatting.locale`: date-fns locales are modules, and
looking one up by tag would put every language in every bundle. Import the one you need.

### Range presets

`createRangePresets` builds the shortcuts a reporting picker offers, in your language and on
your week:

```ts fragment — shape only, not a program
const presets = createRangePresets({
  strings: { thisWeek: "Diese Woche" },
  weekStartsOn: 1,
})
```

Build presets inside the component that renders the picker, from the provider's week —
`useDatesConfig().weekStartsOn` — so "This week" agrees with the calendar beside it. (2.0
removed the English, Sunday-based `RANGE_PRESETS` constant.)

## Right-to-left

`DirectionProvider` from `base/direction` sets direction for a subtree when the document
itself is not RTL. When the whole document is, the `dir` attribute on `<html>` is enough and
the provider is unnecessary.
